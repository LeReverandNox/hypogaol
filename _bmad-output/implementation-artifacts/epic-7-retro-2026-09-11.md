### Significant technical/process events

- **Story 7.3's withdrawal is the epic's defining success, not a footnote.** A full story doc was written, then real-hardware testing (corroborated live by LeReverandNox) proved the planned `--user-presence=false` flag's advertised "zero-interaction unlock" could never actually occur on real FIDO2 hardware — systemd-cryptenroll silently re-enables touch and reports success regardless. The team withdrew the story before any production code shipped, rather than ship a flag that would silently mislead users.
- **Story 1.9's false "fixed" claim regressed real behavior for 6+ weeks, caught only by accident.** Its review record had a checked-off `[Review][Patch]` finding claiming the `base.exists()` mount-point guard was replaced with a uid-stat comparison. `git blame` on the current code disproved it — the block was untouched since the original commit. It was found only because Story 7.2's Task 0 happened to require reading 1.9's file for unrelated context, and its author verified the claim instead of trusting it.
- **The threading/parser-split architecture patterns from Epic 4 (AD-16) and Epic 6 (AD-21) paid for themselves again.** Story 7.1's `client_pin: Option<bool>` mirrored `user_verification`'s threading exactly; Story 7.4's `parse_uv_capable`/`fido2_token_supports_uv` mirrored `parse_client_pin_configured`/`fido2_token_has_pin`'s pure-parser/I/O-wrapper split exactly. Minimal new design decisions needed per story.
- **NFR22's security warning nearly fell through a process crack.** Story 7.1 deferred it to "Story 7.2" (then the NO-UP story); that story was renumbered to 7.3 and later withdrawn entirely, and nobody reassigned the obligation. Story 7.5 only picked it up because its author read 7.1's Dev Notes carefully enough to notice the dangling reference — the same class of gap as Story 1.9's, a written commitment nobody re-verified landed.
- **Self-reported baseline drift recurred a 7th time.** Story 7.1's own Dev Notes claimed 7 pre-existing clippy warnings; re-verified from scratch, the real baseline was 5. Same recurring pattern from Epic 5/6, caught by the next check, no real harm.

## What Went Well

- **Story 7.3's withdrawal**: investigate-before-build discipline caught a structurally impossible feature via real hardware testing before any code shipped, and the epic scope was cleanly reduced (four modes → three) with epics.md, FR27/NFR22/NFR23, and Story 7.5's menu ACs all updated via a proper Sprint Change Proposal.
- **Review discipline held**: every shipped story's review caught a real, substantive bug pre-merge (7.2's orphaned root-owned directory, byte-slice panic risk, and panic-unsafe test cleanup fixed via an RAII guard; 7.5's incorrectly-firing NFR22 warning and an overclaiming UV-annotation).
- **Hardware-verification follow-through**: every story hit the same non-interactive dev-agent environment gap (no interactive sudo, missing `systemd-fido2` plugin in the Nix devshell), and LeReverandNox closed every one of them live, same-day, with precise enough reporting to update the shipped code.
- **Architectural patterns compounding**: AD-16 and AD-21's threading/parser-split precedents let 7.1 and 7.4 ship with almost no new design decisions.

## What Didn't Go As Smoothly

- **Story 1.9's false "fixed" review claim** shipped a real regression for 6+ weeks, caught only by an unrelated story's incidental read of the same file. No mechanism exists today that re-verifies a "fixed" review finding after merge.
- **NFR22's warning nearly went unshipped** after the story it was deferred to was renumbered and then withdrawn — the same underlying failure mode as Story 1.9's, just one epic's worth of luck away from a real security-facing gap shipping silently.
- **Self-reported baseline/count drift recurred a 7th time** (Story 7.1) — the automation action item to fix this at the root has now carried, unaddressed, across three epics.
- **No formal architecture-spine amendment (AD-22)** was authored for Epic 7 despite three of its four stories (7.1, 7.4, 7.5) building on the same "candidate, pending Architect formalization" design note in epics.md.
- **Codecov's wholesale exclusion** of `src/adapters/exec/mod.rs` and `src/cli/main.rs` continues to hide coverage drops in genuinely unit-tested code (`fido2_verification_args`, `parse_uv_capable`, etc.) alongside the hardware-only code it's meant to exclude — carried forward from Epic 7's own Story 7.1 finding, not yet re-challenged.
