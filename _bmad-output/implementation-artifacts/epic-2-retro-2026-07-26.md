## What Went Well

- **Epic 2 was largely wiring, as Epic 1's retro predicted.** `keyslot_guard::remove_keyslot_guarded`, `Fido2Backend::enroll_fido2_key`, `list_fido2_keyslots` — all hardware-verified in Epic 1 — meant Story 2.2 in particular was close to pure orchestration.
- **Story 2.2's review caught two real, non-obvious plain-language bugs** before they shipped: `revoke`'s own `luksKillSlot`/`token remove` failures were falling into a generic "your key/PIN wasn't accepted" message, and shared `luksDump` failures were being mislabeled as enrollment errors.
- **A real UX gap was caught without an AC requiring it**: Story 2.2's review added a "type yes to continue" confirmation gate before revoke executes — nothing in the acceptance criteria asked for it, but revoke is irreversible and security-relevant, unlike `create`'s existing wipe-confirmation.
- **The team fixed its own test-quality gaps quickly**: 2.2's review caught its own `revoke` unit tests asserting "called twice" against a static fake snapshot that never actually proved AD-5's "always live, never cached" guarantee — fixed with a sequence-returning fake before merge, not after.

## What Didn't Go As Smoothly

- **Epic 1's own lesson only half-landed.** Winston's Epic 1 retro lesson: *"any architecture-level claim about external tool behavior should get a throwaway empirical spike before a story signature locks in around it."* Story 2.1 hit the same class of failure twice in a row — first assuming `systemd-cryptenroll` would auto-authenticate with no `--unlock-key-file` (false), then assuming a temporal-diff of `fido2-token -L` enumeration could safely disambiguate two devices (raced, produced hangs and a native "More than one FIDO device found" error) — before the spatial-choice (`Fido2DeviceSelection::Interactive`/`Explicit`) design finally held up on real hardware.
- **"Marker bleed" is now a recurring bug class, not a one-off.** Three separate times, a shared `adapters::exec` error string got mis-attributed to the wrong workflow's plain-language translation: `unlock` swallowed by `enroll`'s `"fido2-token"` marker (fixed in 2.1, commit `e0e44cc`), then `revoke` swallowed by `enroll`'s `"luksDump"`/`"keyslot id"` markers, and `revoke`'s own failures falling into a PIN/touch-specific message that made no sense for a non-interactive header edit (both fixed in 2.2). Every new workflow that reuses shared adapter helpers seems to trip this the same way.
- **Testing kept finding its own blind spots one hardware run at a time**: a label-survival assertion that grepped human-readable `luksDump` text instead of the parsed JSON field (never could have passed), and an unlock test that didn't actually force a key swap between two keys, so it silently proved nothing about which key unlocked. Both were test bugs, not product bugs, and both were only caught by physical hardware runs — consistent with the Project Lead's read that this is inherent to a tool whose correctness depends on real external hardware interop, not a process failure to fix away.
- **A tooling gap made a real design fix look like a regression**: the `Makefile`'s `test-hardware` target didn't pass `--nocapture`, so the new numbered device-picker prompts were silently swallowed by `cargo test`'s stdout capture, making a correct implementation look like a hang.

## Epic 3 Preview: Tomb Lifecycle & Advanced Access

- **No significant discoveries requiring an Epic 3 re-plan.** Epic 2's device-selection design doesn't affect Epic 3's stories (close/resize/read-only unlock do no enrollment).
- **One scoping dependency carried from Story 1.9's own deferred-work list**: `close` (Story 3.1) needs to explicitly decide whether it `rmdir`s the plain-basename mount-point directory after unmounting — if it doesn't, re-unlocking the same tomb permanently falls back to a suffixed directory name. Not a blocker, but must be a deliberate decision when 3.1 is scoped, not an oversight.
- **Watch item, raised again**: the `sudo`-for-device-ops documentation gap (open since Epic 1) will resurface for Epic 3's `resize` on raw devices, the same permission wall Epic 1 and 2 both deferred.
