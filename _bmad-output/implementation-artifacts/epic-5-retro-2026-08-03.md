- Clean scope discipline across all 4 stories despite heavy file overlap (README.md alone was touched by 5.1, 5.2, and 5.3) — each story's Dev Notes explicitly cited the sprint-change-proposal's per-story split and refused to pull in adjacent-story work.
- AD-13 (placeholder-name isolation, decided back in Epic 1) paid off exactly as designed: Story 5.1 changed exactly one identifier (the Cargo package name) and the CLI banner followed automatically with zero code change.
- Story 5.2 caught and fixed its own incidental "volume's LUKS2 volume" stutter (a genuine terminology collision the mechanical rename exposed) in the same commit rather than shipping confusing text.
- Story 5.4 justified a deliberate, explained scope expansion — epics.md's AC only named one automation file, but a grep proved three more live `_bmad/custom/*.toml` files carried the same stale repo path; the story documented its reasoning rather than silently expanding or silently skipping.

## What Didn't Go As Smoothly

- **A new recurring pattern: self-reported completion claims not matching actual verification output**, hit in all four stories:
  - 5.1: Completion Notes claimed "no hardcoded `tomb-fido2` literals anywhere in `src/`" — false; review found 12 in `src/cli/ux.rs`.
  - 5.2: `cargo fmt --check` failures in 3 touched files went undetected until review.
  - 5.3: Completion Notes claimed "~90" doc-comment lines reviewed for tone; actual count was 160.
  - 5.4: no functional miss, but review surfaced the exact gap this retrospective now closes (no tracked action item for the Epic 5 retro itself).
  - None of these caused a shipped regression — all were caught pre-merge — but four-for-four is a real pattern, distinct from Epic 4's "untested parsing function" pattern. Worth an explicit watch, the same way that one is.
- The Epic 3 resize grow-only bug's third recurrence (via Story 5.2's hardware run) with no assigned owner — LeReverandNox decided in this retro to address it before Epic 6 rather than let it stand for a fourth.
