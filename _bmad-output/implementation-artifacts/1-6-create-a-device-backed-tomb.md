# Story 1.6: Create a Device-Backed Tomb

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a user,
I want to create a new tomb on an existing raw device or partition, optionally reserving free space,
so that I can use the tool directly against physical storage without an intermediate file.

## Acceptance Criteria

1. **Given** a device/partition path with no existing LUKS2 header and no size given, **when** I run the create command in device mode and confirm the wipe/data-loss warning, **then** the tool defaults to the device's full capacity, formats it as LUKS2, creates the filesystem, and bootstrap-enrolls my first FIDO2 key. [Source: epics.md#Story 1.6]
2. **Given** a size smaller than the device's actual capacity, **when** I confirm the wipe warning and proceed, **then** the tool uses exactly the requested size, leaving the remaining capacity free for a later resize/grow. [Source: epics.md#Story 1.6]
3. **Given** a size argument larger than the device's actual capacity, **when** I run the create command in device mode, **then** the tool refuses with a clear error before touching anything. [Source: epics.md#Story 1.6]
4. **Given** a device/partition that already carries a LUKS2 header, **when** I run the create command in device mode, **then** the tool refuses before touching anything, regardless of whether I attempt to confirm the wipe warning. [Source: epics.md#Story 1.6]
5. **Given** a device/partition with no existing LUKS2 header, **when** I run the create command in device mode without confirming the wipe/data-loss warning, **then** the tool refuses to proceed — confirmation is mandatory for every device-backed create, not just when a header is detected. [Source: epics.md#Story 1.6]

- **Correction discovered during implementation: `cryptsetup luksFormat --size`/`-b` does not work on this machine's cryptsetup 2.8.6.** The story's Task 2/5 text (and the architecture doc's literal method signature) assumed `luksFormat --size <sectors>` constrains the LUKS2 payload. Empirically running it returns `cryptsetup: Option --size is not allowed with luksFormat action` — confirmed against `man cryptsetup-luksFormat`'s own `<options>` list, which does not include `--size`/`--device-size` for the `luksFormat` action (nor for LUKS `open`). This is a same-signature adapter-internals-only fix — the `LuksBackend` port signature, `DomainError` variants, and `domain::workflows::create`'s Device arm from Tasks 1-4 are all unaffected and unchanged.
