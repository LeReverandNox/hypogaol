## What Went Well

- Full 6-story scope shipped clean: zero regressions, zero production incidents, only one deliberate quality hold (not a technical failure).
- **Marker-bleed — the dominant recurring bug class from Epics 2 and 3 — did not resurface**, despite five workflow-touching stories each threading new parameters through shared call sites (25–39 call-site updates per story).
- Real architectural discipline held under pressure: five separate epics-vs-code conflicts (4.2's enroll-before-mkfs ordering, 4.3's AD-16, 4.4's AD-12/AD-14 read-only-awareness question, 4.5's missing `dmsetup` preflight dependency) were each resolved by treating the architecture spine as binding over looser epics prose, with each story explicitly citing the prior resolution as precedent.
- 4.6's quality-gate hold — refusing to accept a story as `done` on a false hardware-verification claim — is exactly the kind of self-correcting process behavior a retrospective exists to reinforce.
- LeReverandNox's own hardware dogfooding (4.3's clientPin discovery) once again found a real security-relevant gap no unit test or review pass could have — consistent with the pattern named in the Epic 2 and 3 retros.

## What Didn't Go As Smoothly

- **A new recurring pattern replaced marker-bleed**: new pure parsing/logic functions shipped without unit tests three separate times (4.3's `fido2_verification_args`, 4.5's `loop:`/`device:` field parser, 4.6's `fuser -m` PID parser), each caught only in review. Worth naming explicitly so the next epic watches for it proactively, the way marker-bleed now is.
- Three backlog items (sudo docs, LICENSE, the swallowed-rollback pattern) went unaddressed across four consecutive retrospectives before finally being closed — not because any of them caused a real incident, but because "not blocking, so it's fine to defer again" has limited shelf life as a habit.
- The originally proposed fix for the rollback pattern (a bare `tracing::warn!` at three call sites) turned out to be wrong on inspection: no `tracing` crate exists in this project, and `src/domain/` holds a hard zero-direct-I/O invariant. The real fix needed a new `DomainError::RollbackCleanupAlsoFailed` variant that wraps the original error (preserving its own translation) rather than a same-day log line — a reminder that "small, obvious" fixes proposed off the cuff in a retro still deserve the same scrutiny as story work before landing.
