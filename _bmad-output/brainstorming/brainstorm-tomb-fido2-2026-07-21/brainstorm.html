Technique I

One Feature Only

every other box in the vault wall stays shut — one box, one key, one job: unlock LUKS volumes with a FIDO2 security key

Idea

The one feature kept: unlock LUKS-encrypted volumes using FIDO2 security keys.

Insight

The design goal isn't a wow-effect unlock experience — it's dead-simple, boring reliability: “I can trust it with my life.”

Idea

Core use case: cold storage for rarely-accessed, highly sensitive material (master GPG key, password manager backup) — like a bank safe, opened once a year in a crisis, that must unlock without hesitation.

Decision

Scope boundary: key/volume backup strategy (3-2-1, spare FIDO2 keys) is the user's responsibility, not the tool's concern — the tool stays unaware of it.

Decision

Multi-key enrollment is in scope: supporting multiple FIDO2 keys as alternate unlock methods on the same volume via LUKS2's native multi-keyslot support (up to 32 slots) — still counts as "the one feature."

Insight

Tool philosophy: a thin, user-friendly abstraction layer over LUKS2 + FIDO2 hmac-secret — not reinventing crypto, just enough sugar to make native LUKS2 features (multi-keyslot enroll/revoke) simple to use.

Idea

Core friction the tool solves: replacing a multi-tool memorization burden — cryptsetup + fido2-token + systemd-cryptenroll, each with their own flags — with one tool, simple commands, simple args. No hunting through notes or searching the web during a crisis.

Technique II

Job to Be Done

Job posting The job being hired: store sensitive information securely, without relying on any third party or external service/tool.
Cautionary reference · May 2014

TrueCrypt shuts down, without warning

For critical use cases, the lesson is to rely on the simplest, lowest-level, most standard, well-tested tools — LUKS/dm-crypt — rather than proprietary or single-vendor-maintained solutions. A tool can vanish overnight; the primitives underneath it shouldn't.

In case of emergency

Break-glass requirement: the README must document how to manually unlock the volume using only standard cryptsetup + fido2-token commands — with zero dependency on the tomb-fido2 binary itself surviving.

Rejected

Rejected reversal: physical key presence at unlock time is not up for challenge. The tool should support exactly whatever unlocking methods cryptsetup's token/FIDO2 mode natively offers — no more, no less.

Technique IV

Emerging Tech Collision

Post-quantum crypto
Decision

Post-quantum threat explicitly deprioritized: if classical asymmetric crypto breaks, the world has bigger problems than encrypted volumes. Being able to still open volumes and extract data via standard tools is future-proof enough.

Convergence

MoSCoW Scope — Final State

two rounds of scoping decisions, merged into one drawer set — the corrected backup wording and the later-added block-device requirement both reflected below

Must

  • Unlock LUKS volumes with a FIDO2 key
  • Multi-key enrollment (add keyslot)
  • Key revocation (remove single keyslot)
  • One unified CLI replacing cryptsetup + fido2-token + systemd-cryptenroll
  • Plain-language terminal guidance, assuming zero FIDO2 knowledge
  • Pre-flight dependency check with clear error exit
  • Support LUKS2 on raw physical block devices/partitions, in addition to file-backed loop devices

Should

  • README-documented break-glass manual recovery procedure
  • README recommends a 3-2-1 backup strategy as a disclaimer only — the tool itself remains entirely unaware of backups; no code or feature touches this

Won't this time

  • Remote/delegated unlock beyond cryptsetup's native token mode
  • Post-quantum-readiness features
The Vault Opens

This is not “Tomb but modernized.” It's proof that Tomb's real innovation — a thin wrapper over standard, boring primitives that survives the tool's own death — was primitive-agnostic all along, now re-applied to FIDO2 instead of GPG and keyfiles.

Chosen direction: a FIDO2-only LUKS2 unlock tool, in Go or Rust, scoped exactly per the Must / Should / Won't list above — with crisis-reliability and zero-FIDO2-knowledge UX as the driving design constraints.
